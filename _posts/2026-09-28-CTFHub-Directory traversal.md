# CTFHub Writeup - 目录遍历

## 题目类型

Web

## 题目描述

<br>进入点击开始寻找flag之后显示：
<br>Index of /flag_in_here
<br>[ICO]	Name	Last modified	Size	Description
<br>[PARENTDIR]	Parent Directory	 	-	 
<br>[DIR]	1/	2026-09-28 13:25	-	 
<br>[DIR]	3/	2026-09-28 13:25	-	 
<br>[DIR]	4/	2026-09-28 13:25	-	 
<br>Apache/2.4.38 (Debian) Server at challenge-793de6b6c5faf6d4.sandbox.ctfhub.com Port 10800

## 解题过程
<br>页面出现四个文件夹，依次在文件夹中寻找，由于每个文件夹进入后还会出现相同的四个文件夹，使用排列组合依次进入文件夹，最终在Index of /flag_in_here/2/3中找到flag.txt，成功获得flag

## 疑问与解答

### 1.

问：页面中的“Index of /flag\_in\_here”表示什么？
<br>答：这是目录索引页面，Web 服务器将该目录下的父目录入口和子目录直接展示给访问者，可能因此暴露敏感资源的位置。



### 2.

<br>问：目录索引、目录枚举和路径穿越有什么区别？
<br>答：目录索引是服务器主动列出目录内容；目录枚举是探测或逐层访问可能存在的资源；路径穿越则是利用路径处理缺陷，通过类似“../”的路径逃离应用限定的目录。



### 3.

<br>问：本题是否存在真正的路径穿越漏洞？
<br>答：现有证据只显示目录列表和数字子目录，因此可能主要考查目录索引暴露与目录枚举；由于没有记录具体取 Flag 的操作，无法确认是否还存在利用“../”读取目录外文件的路径穿越漏洞。


## 本题的核心逻辑：



<br>目录索引会将服务器目录中的文件和子目录直接暴露给访问者。面对公开的目录层级，可以根据当前路径、父目录入口和子目录继续定位资源，这体现了目录结构泄露带来的安全风险。

<br>根据页面列出的“1/”至“4/”等子目录推断，服务器可能启用了 Apache 目录索引功能，并且目标目录缺少默认首页文件或被配置为允许列出内容，因此疑似存在服务器配置不当导致的信息泄露。

<br>防御此类问题应关闭不必要的目录索引，为敏感目录配置身份认证和访问控制，并避免将 Flag、备份文件、源码或配置文件放在可公开访问的 Web 目录中；隐藏链接不能替代权限控制。


## 笔记

这道题主要学习了：

<br>1. 遇到目录列表页面时，应关注当前路径、父目录入口和各级子目录之间的关系；公开可见的目录结构本身就可能泄露敏感资源的位置。
<br>2. 题目名称不一定等同于严格的漏洞分类，应依据实际页面和操作区分目录索引暴露、目录枚举与路径穿越，避免将所有目录相关问题都理解为“../”利用。
<br>3. 防御目录信息泄露不能只依赖隐藏链接，还应关闭不必要的目录索引、配置访问控制，并避免将敏感文件放在公开的 Web 目录中。
