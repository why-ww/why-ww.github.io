# CTFHub Writeup - HG泄露

## 题目类型

Web

## 题目描述

题目名称：HG泄露；平台：CTFHub；方向：Web。

## 解题过程

<br>1. 设置靶机地址：B=http://challenge-6f1cf2bd96877574.sandbox.ctfhub.com:10800。
<br>2. 访问 $B/.hg/requires，响应列出 dotencode、fncache、generaldelta、revlogv1、sparserevlog、store，确认 .hg 目录可被直接读取。
<br>3. 访问 $B/.hg/store/fncache，得到 data/index.html.i、data/50x.html.i、data/flag\_1672427088.txt.i 三个文件记录，其中出现 flag\_1672427088.txt 对应的文件日志路径。
<br>4. 下载 $B/.hg/store/00changelog.i 到本地 00changelog.i，并用 Python 的 zlib 解压其中可识别的 zlib 数据流；输出包含两次提交信息：init（涉及 50x.html、index.html）和 add flag（涉及 flag\_1672427088.txt）。
<br>5. 尝试读取该文件自己的文件日志 $B/.hg/store/data/flag\_1672427088.txt.i 时返回 404，记录中说明部署时没带上该文件。
<br>6. 随后直接访问 web 根目录下的 $B/flag\_1672427088.txt，得到 ctfhub\{871a7dbf0216bf91d7f90460\}。

## 疑问与解答

### 1.

<br>问题：为什么访问 .hg/requires 能确认 HG 泄露？
<br>解答：.hg 是 Mercurial（HG）仓库的元数据目录，requires 用于描述仓库格式和所需特性；如果 Web 服务能直接返回该文件，说明版本控制元数据没有被正确屏蔽，可能进一步泄露 store、fncache 和 changelog 等内容。

### 2.

<br>问题：fncache 和 00changelog.i 在 HG 泄露中分别有什么作用？
<br>解答：fncache 记录仓库中文件的存储路径，可帮助定位被跟踪文件；00changelog.i 保存提交历史相关数据，解压后可看到提交说明和涉及的文件。本题中二者共同暴露了 flag\_1672427088.txt 这一目标文件名。

### 3.

<br>问题：文件日志返回 404 是否意味着无法获取 flag？
<br>解答：不一定。从记录看，flag 文件本身仍在 web 根目录可直接访问，因此可能无需还原该文件日志即可读取内容；404 可能只是对应的 .i 文件未部署或不可访问。


## 本题的核心逻辑：

<br>HG（Mercurial）仓库的 .hg 目录保存版本控制元数据；若 Web 服务器未禁止访问该目录，requires、store/fncache 和 00changelog.i 等文件就可能被直接读取，形成源码与历史信息泄露。

<br>本题中，fncache 和 changelog 暴露了 flag\_1672427088.txt 的存在及提交记录；虽然该文件的 .i 文件日志返回 404，但目标文件本身仍位于 web 根目录，最终通过直接访问取得 flag。


## 笔记

这道题主要学习了：

<br>1. Mercurial 的 .hg 目录是版本控制元数据入口，requires 可确认仓库格式，fncache 可列出跟踪文件路径，00changelog.i 可用于还原提交历史；这些文件一旦被 Web 直接暴露，就可能泄露源码、历史版本和敏感文件名。
<br>2. 遇到版本控制元数据泄露时，应优先检查元数据目录是否可访问，再结合文件清单和提交历史定位目标；同时不要忽略目标文件可能仍直接存在于 web 根目录的情况。
