# CTFHub Writeup - .DS\_Store

## 题目类型

Web

## 题目描述

题目名称：.DS\_Store；平台：CTFHub；方向：Web。

## 解题过程

1. 用户发现网站根目录下存在 .DS\_Store 文件，在 URL 后加上 .DS\_Store 进行访问，读取到了目录下的文件名，并注意到其中有一个 txt 文件。
2. 用户用记事本打开获取到的文件，从中得到文件名 3ad965b471a9809723e94c470f87a14b.txt。
3. 用户访问 http://challenge-fb8cd18d97787405.sandbox.ctfhub.com:10800/3ad965b471a9809723e94c470f87a14b.txt，记录称即可获得 flag。

## 疑问与解答

### 1.

<br>问：.DS\_Store 是什么，为什么能泄露目录中的文件名？
<br>答：.DS\_Store 是 macOS Finder 用于保存目录显示属性等元数据的隐藏文件，其中可能记录该目录下的条目名称。若网站根目录误上传了该文件且服务器允许直接访问，访问者就可能从中获取原本不易发现的文件名。



### <br>2.

<br>问：为什么拿到 txt 文件名后可以直接构造 URL 访问？
<br>答：如果该 txt 文件位于 Web 可访问目录中，服务器又没有禁止访问该路径，那么把泄露出的文件名拼接到站点根 URL 后即可请求该资源；哈希式文件名难以直接猜解，泄露的价值在于提供了准确路径。

<br>

### <br>3.

<br>问：这类题目的防护要点是什么？
<br>答：应避免把 .DS\_Store 等系统或编辑器元数据文件部署到 Web 根目录，并在服务器层面禁止访问以点开头的隐藏文件；同时不要依赖难以猜测的文件名作为唯一保护手段。


## 本题的核心逻辑：




<br>本题利用的是 Web 目录中的元数据文件泄露：.DS\_Store 可能包含目录条目名称，攻击者读取后可以还原出隐藏文件名，再据此构造资源 URL。该利用链依赖两个条件，即 .DS\_Store 可被直接访问，以及泄露出的文件本身位于 Web 可访问路径。


## 笔记

这道题主要学习了：

<br>1. 技术点在于识别并读取 Web 根目录下的 .DS\_Store 文件，从其内容中提取目录内的文件名，再拼接站点地址访问目标资源。
<br>2. 原理是系统元数据文件被错误部署到公开目录，导致目录条目名称等信息泄露；难以猜解的文件名一旦泄露，就可能被直接请求。
<br>3. 后续可进一步了解服务器对隐藏文件的访问控制、常见编辑器与系统元数据文件的泄露风险，以及如何从泄露信息中还原可访问路径。
