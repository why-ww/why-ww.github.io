# CTFHub Writeup - 响应包源代码

## 题目类型

Web

## 题目描述

网页是一个贪吃蛇游戏，下方有开始，暂停，继续按钮，还有蛇的坐标，长度显示

## 解题过程

<br>1. 根据题目名称，确定使用 Burp 抓取浏览器与服务器之间的 HTTP 请求和响应。
<br>2. 使用 Burp 完成抓包并发送请求，随后查看服务器返回的响应内容。
<br>3. 检查响应源码时，在第 25 行的 HTML 注释中找到了 Flag 信息。

## 疑问与解答

### 1.

<br>问题：服务器返回的页面文本中没有 Flag 时，应该检查什么？解答：应检查主 HTML 响应的原始正文，重点关注 HTML 注释等不会显示在页面上的源码内容；还可搜索 \`flag\`、\`ctfhub\`、\`\<\!--\` 等关键字。



### 2.

<br>问题：为什么 HTML 注释中的内容在网页上看不到？解答：浏览器会解析 \`\<\!-- ... --\>\` 为注释并跳过其可视化渲染，但注释仍存在于服务器返回的 HTML 响应正文中，可以通过 Burp、开发者工具或查看页面源代码发现。



### 3.

<br>问题：怎样判断抓到的是主页面响应？解答：通常可结合请求目标、状态码、\`Content-Type\` 和正文结构判断；主 HTML 响应一般返回 HTML 文档，而不是单独的脚本、图片或接口数据。


## 本题的核心逻辑：



<br>1.浏览器呈现的可见页面只是 HTML 经过解析和渲染后的结果，并不等同于完整的 HTTP 响应源码。HTML 注释不会显示在页面中，但仍会随响应发送到客户端。

<br>2.本题的关键是绕过对贪吃蛇可见界面的关注，直接检查主页面响应源码，并从第 25 行的注释中定位 Flag 信息。

<br>3.现有证据表明信息被放在 HTML 注释中，可能属于源码敏感信息暴露；但证据不足以将其认定为某一种更具体的 Web 漏洞。


## 笔记

这道题主要学习了：

<br>1. HTML 注释不会出现在网页可见内容中，但仍完整保留在服务器返回的 HTML 源码里。
<br>2. 分析 HTTP 响应时，应区分浏览器渲染结果与原始响应正文，并关注注释等未被渲染的源码部分。
<br>3. 本题的解题链路是使用 Burp 查看响应内容，再检查 HTML 注释并定位 Flag。
