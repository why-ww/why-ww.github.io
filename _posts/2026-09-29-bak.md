# CTFHub Writeup - bak文件

## 题目类型

Web

## 题目描述

<br>当开发人员在线上环境中对源代码进行了备份操作，并且将备份文件放在了 web 目录下，就会引起网站源码泄露。
<br>提示Flag in index.php source code.

## 解题过程

<br>1. 通过修改 URL 后缀，找到了网站中的备份文件。
<br>2. 根据备份文件常用的 .bak 后缀和题目提示，尝试访问 index.php.bak。
<br>3. 获得备份文件后，使用 VS Code 打开文件并找到了 Flag。

## 疑问与解答

### 1.

问：常见的网站源代码备份文件后缀有哪些？答：常见后缀包括 .bak、.old，以及编辑器生成的波浪号后缀（~）。本题标题为“bak文件”，因此 index.php.bak 是与题目线索最直接对应的路径。

<br>

### <br>2.

问：为什么访问备份文件能够看到 PHP 源代码？答：正常访问 .php 文件时，服务器通常会将 PHP代码交给解释器执行；而带有未被服务器识别为 PHP 脚本的备份后缀时，文件可能被当作普通静态文件返回，从而暴露源代码。


## 本题的核心逻辑：



<br>题目描述指出，开发人员将源代码备份文件放在了 web目录下。公开目录中的备份文件可能可以通过 URL直接访问，而 .bak 后缀会使服务器不再按原 PHP 文件执行，进而造成源码泄露。

<br>结合题目提示“Flag in index.php source code”和已找到 index.php.bak 的记录，可以推断 Flag 位于泄露的 index.php备份源码中。


## 笔记

这道题主要学习了：
<br>1. 遇到提示源码位于 index.php 的题目时，可以结合题目标题和常见备份命名规则，优先检查对应的 .bak 文件。
<br>2. 以后进行 Web 安全检查时，可以重点关注 Web目录中是否存在可被直接访问的源码备份文件，因为这类文件可能造成敏感代码泄露。
