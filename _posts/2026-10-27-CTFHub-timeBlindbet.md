# CTFHub Writeup - 时间盲注

## 题目类型

Web

## 题目描述

时间盲注
什么都不返回，试试吧

ID


## 解题过程

<br>1. 先定义探测函数 q(payload)：用 curl.exe 请求 $u/?id=$payload，其中 $u 为挑战地址，输出状态码、响应字节数和总耗时；记录中的判定标准为耗时小于 0.6s 判假、大于 0.8s 判真、处于中间则重试。
<br>2. 确认注入点时，调用 q 探测 id=1 返回 200、1157B、0.219s；调用 q 探测 1%20and%20sleep(3) 返回 200、1170B、3.198s，记录标注延迟 3 秒且 and 进入了 SQL。
<br>3. 闭合方式探测中，调用 q 探测 1'%20and%20sleep(3)--%20- 返回 200、1175B、0.204s，记录标注不延迟。
<br>4. 确认表名/列名时，探测 (select count(\*) from flag)\>0 的 if 条件返回 200、1206B、1.182s，记录标记表存在；探测 flag 列 is not null 的条件返回 200、1229B、1.189s，记录标记列存在。
<br>5. 同一阶段用包含 select nope from flag 的条件探测返回 200、1208B、0.186s，记录标注报错被吞、不延迟。
<br>6. 二分测长度时，length((select flag from flag limit 1))\>15 返回 1.217s（真），\>31 返回 1.185s（真），\>32 返回 0.192s（假）。
<br>7. 二分测字符时，对第 8 位使用 ord(substr((select flag from flag limit 1),8,1))\>50 返回 1.191s（真），\>55 返回 0.188s（假）；记录标注 50 \< 54 ≤ 55，因此 chr(54)='6'。
<br>8. 整串校验时，条件 (select flag from flag limit 1)='ctfhub%7B659de4bf9dc8f2a79b7803bc%7D' 配合 sleep(2) 返回 200、1243B、2.192s，记录标记全等→真；在字符串后追加 \_x 的对照返回 200、1245B、0.231s，记录标记假。

## 疑问与解答

### 1.

<br>问题：时间盲注如何把 SQL 条件真假转化成可观测信号？
<br>解答：通常用 if(condition,sleep(n),0) 或 and sleep(n)，条件为真时让数据库延迟响应；先测正常请求的基线，再用耗时阈值判断真假。本题记录中 sleep(3) 对应 3.198s，sleep(1) 对应约 1.18s，说明延迟可作为判据。

### 2.

<br>问题：为什么单引号闭合的 sleep 探测没有延迟？
<br>解答：从记录看，1 and sleep(3) 产生 3.198s 延迟，而 1' and sleep(3)-- - 只有 0.204s；这可能说明注入点并非该单引号闭合形式，或注释符与后端 SQL 语法不匹配，需要继续枚举闭合方式。

### 3.

<br>问题：为什么二分法适合时间盲注？
<br>解答：每个字符可按 ASCII 范围用 ord(substr(...,pos,1)) \> mid 反复比较，约 7 次即可定位一个可打印字符；长度也可先二分确定。这样能减少请求次数，降低盲注耗时和网络抖动影响。


## 本题的核心逻辑：


<br>时间盲注适用于页面不回显查询结果、布尔差异也不明显的情况；它把 SQL 条件编码进 if(condition,sleep(n),0) 一类表达式，条件为真时响应被延迟，从而把数据判断转化为耗时判断。本题记录先用 sleep(3) 确认 SQL 可执行，再用 if 条件探测表名、列名、长度和字符。

<br>逐字符二分是时间盲注的常用加速方式：用 length 判断长度，用 ord(substr(...,pos,1)) 与中值比较，将每个字符的搜索空间压缩到对数级；最后可用整串相等条件做一次校验。本题记录中全等条件触发 sleep(2) 约 2.192s，而追加字符的对照约 0.231s，体现了这种真假编码。


## 笔记

这道题主要学习了：

<br>1. 时间盲注的判定依赖响应耗时而非页面内容，因此先建立稳定基线，并通过多次测量和重试来区分网络抖动与真实延迟；同时把 sleep 时长设置得明显高于正常响应耗时，以降低误判概率。从记录看，普通响应约 0.2s，sleep(1) 约 1.18s，sleep(3) 约 3.198s，因此用耗时阈值判断 if 条件真假是可行的。
