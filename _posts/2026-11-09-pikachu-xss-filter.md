# Pikachu Lab - xss之过滤

## 实验模块

模块：XSS

场景：xss之过滤

## 漏洞场景

题目名称：xss之过滤；平台：Pikachu；方向：Web。

## 测试过程

<br>1. 首先在输入框提交基础 Payload：\<script\>alert(1)\</script\>，点击 submit 后页面出现过滤提示：“别说这些'\>'的话,不要怕,就是干\!”，说明该 Payload 被拦截。
<br>2. 随后测试特殊字符，分别输入单个 \>、\<\> 以及特殊字符组合；记录显示单个 \> 和 \<\> 等组合可以正常通过，没有被直接拦截。
<br>3. 将 Payload 中的 script 标签改为大写，提交 \<SCRIPT\>alert(1)\</SCRIPT\>；页面成功弹出 JavaScript 提示框并显示 1，验证了大写形式可以绕过当前过滤。
<br>4. 用户进一步分析认为，过滤程序很可能采用区分大小写的字符串匹配或正则表达式；只匹配小写 \<script\> 时，大写 \<SCRIPT\> 可能无法被匹配，而浏览器仍能识别并执行该标签。

## 其他观察

从单个 \> 与 \<\> 未被直接拦截这一现象推测，当前过滤并非简单地删除所有尖括号，而可能只针对特定字符串或标签模式进行匹配。

大小写形式成功触发弹窗，推测过滤规则可能没有统一进行大小写归一化处理，导致黑名单匹配与实际浏览器解析之间出现差异。


## 分析与解答

### 1.

<br>问题：为什么 \<SCRIPT\>alert(1)\</SCRIPT\> 能绕过过滤并执行？
<br>解答：如果服务端过滤只按小写 \<script\> 做区分大小写的匹配，那么大写标签不会被该规则命中；但 HTML 标签名在浏览器解析时通常不区分大小写，因此 \<SCRIPT\> 仍会被当作脚本标签执行。

### 2.

<br>问题：这类过滤问题反映了什么 XSS 防御误区？
<br>解答：仅依赖简单的字符串黑名单容易遗漏大小写变形、标签变体或属性事件等写法；防御应对输入进行严格白名单校验，并在输出到 HTML 上下文时进行正确的实体编码，而不能只匹配某一种固定写法。


## 漏洞原理与修复思路

<br>本题体现的是反射型 XSS 场景下的黑名单过滤绕过：过滤逻辑若只匹配小写 script 标签，便可能被大小写变体绕过，而浏览器对 HTML 标签名大小写不敏感，最终仍会解析并执行脚本。

<br>修复时应在服务端统一进行大小写不敏感的危险标签和属性检测，优先采用白名单策略，并根据输出上下文使用 HTML 实体编码；同时可结合 CSP 等浏览器侧策略降低脚本执行风险。


## 学习总结

本次靶场实验主要学习了：

<br>1. 本题的关键技术点是理解过滤规则与浏览器解析规则之间的差异：过滤端可能区分大小写，而 HTML 标签解析通常不区分大小写，这种差异可以形成 XSS 绕过空间。
<br>2. 测试过滤时，先确认基础 Payload 是否被拦截，再通过特殊字符和大小写变形观察过滤边界，有助于推断黑名单匹配方式；后续学习可继续关注不同上下文中的编码与白名单防御。
